# Base Wars - code map

One authoritative **server** executable and one **client** executable (C++23, EnTT, Raylib, Steamworks). No other targets.

```
CMakeLists.txt, CMakePresets.json (release, asan), .clang-format
cmake/        Compiler, Dependencies (raylib, EnTT), Steamworks (mandatory SDK), Assets, Targets, WriteClientConfig
config/       server.cfg  - documented server tuning, copied next to the server executable
assets/       art, shaders, Tiled UI maps (assets/ui, generated by tools/gen_ui_maps.py)
tools/        check.sh (the gate), shot.sh (screenshot run with retries), asset / UI generators (python)
src/common/   KindDefs.hpp (kind registry: KINDS table, KT_* tags), Shared.hpp (enums, protocol Msg) + WorldGen / Placement / Serialization,
              Progression.hpp (Town Hall gates, level/cost/time curves), ServerConfig (config/server.cfg loader)
src/components/  data-only EnTT components (server side)
src/networking/  SteamServerNet / SteamClientNet (Steam Networking Sockets), SteamClient (login/friends), ServerBrowser
src/server/   World (shared server state + entity helpers), Sim (system order per tick), Invariants (checkInvariants), ServerMain (main + net loop), SelfTests (+ selftests/*.cpp)
src/systems/  one class per server system (DefeatSystem = ruin + resettlement), all taking World& and Systems& (see Systems.hpp)
src/client/   App (frame loop), Session, PacketHandler, Commands, Input, Placement, ClientWorld, TestHooks, Settings
src/rendering/  renderers (terrain, water, buildings, units, ships, effects, post-fx, minimap), Assets, Bars, Sprites
src/ui/       widgets (CostRow, tabs, sliders, arrows) and panels (Hud, BuildMenu, ContextPanel, TrainingPanel = Archery,
              TownHallWindow(+Tabs), SocialMenu, Chat, PauseMenu, MainMenu, BigMap, ShipPanel)
```

Headers sit beside their `.cpp`. No `.inc` files. Files should stay readable (guideline ~600 lines).

## Build

* Requires the Steamworks SDK in `third_party/steamworks` (folder containing `public/steam/steam_api.h`; git-ignored) or `-DSTEAMWORKS_SDK_DIR=<path>` / `STEAMWORKS_SDK` env var.
* `cmake --preset release && cmake --build build/release`. Post-build steps copy `steam_api`, `steam_appid.txt` (480), `config/server.cfg` (server), `config.txt` and a link/copy of `assets/` (client). `compile_commands.json` is exported.
* `cmake --preset asan` builds with AddressSanitizer + UBSan (MSVC: ASan only; the runtime DLL comes from the VS environment). Zero warnings in every preset (`cmake/Compiler.cmake`: `/W4` or `-Wall -Wextra`, `-DBW_WERROR=ON` makes them errors; `tools/check.sh` sets it).
* On Windows run builds and `tools/check.sh` from a shell with the MSVC environment (vcvars64) or set `BW_VCVARS` to the path of `vcvars64.bat`.

## Testing and verification

* `tools/check.sh` is the gate: release + asan builds, all selftests, clang-format check. Docs-sync (every `BW_*` env hook and selftest name appears in this file) and header checks are advisory warnings.
* **Selftests:** `server --selftest <name|list|all>`. Headless: no Steam, fixed seed, fast-forwarded ticks, deterministic, exit 0/1. Registered by name in `src/server/SelfTests.cpp`, one file per feature under `src/server/selftests/`.
  Every feature task adds a scenario with numeric assertions. Baseline: `boot`, `saveload` (save -> load -> save byte-identical, so saves must be written in a deterministic order), `economy`, `raid`, `net-garbage`, `invariants` (the checker catches an orphaned job), `identity` (SteamID-only ownership, forged / pending / timed-out logins), `defeat` (burning ruin, resettle offers, blocked commands, timeouts), `net-snapshot` (chunk size cap, lost chunks, seq echo / replay rejection, protocol version).
  Scenarios use `selftest::Fixture` (a `Sim` = World + Systems, offline transport, fake connections via `join`, `run(seconds)`); `Sim` (`src/server/Sim.cpp`) holds the tick order shared with the real server loop.
* **Invariants:** `World::checkInvariants()` (always on in selftests, `BW_INVARIANTS=1` in real runs): stored entities valid, no job / ship / caravan / garrison referencing a dead entity, resources >= 0, footprints do not overlap, at most one Town Hall per owner, timed states have expiries.
  A new component that can dangle adds its check here.
* **Stuck-state rule:** every player-facing state has a guaranteed exit and a selftest proving it.
* **Visual checks:** scripted client run with `BW_SHOT` (`tools/shot.sh` retries); optional evidence, not part of the gate.
* **Limits:** headless tests cover server simulation. Rendering, UI feel, interpolation and prediction need an occasional human playtest (see checkpoints in `TODO.md`).

## Networking

* Steam GameServer + Steam Networking Sockets only. The server opens an IP listen socket (direct, `IP_AllowWithoutAuth`) and a P2P listen socket (Steam Datagram Relay, reachable by SteamID).
* `server <port> <seed> <savefile> <name> [--local]`: `--local` skips the Steam backend login (direct IP only). The Steam client must run for both executables except for `--selftest`.
* Client: `client --connect host:port` joins directly; the menu has Internet / Friends / Direct tabs.
* **Envelope (T19a, `common/Snapshot.hpp`, `PROTOCOL_VERSION` = 2):** `C_Hello` = `u16 version, ...`; `S_Welcome` starts with `u16 version`; a mismatch is refused with a text (server) / back to the menu (client).
  Every client command except `C_Hello` carries a `u32 seq` right after the type byte (`Session::send` stamps it, strictly increasing per connection; the server drops missing / replayed / reordered seqs and keeps `Profile::lastInputSeq`).
* **Snapshots:** the server runs a fixed 20 Hz tick; every `snapshot_interval_ticks` (default 2) each online player gets one full `S_State`, sent **unreliable** as chunks of at most `SNAPSHOT_MTU` (1100) bytes.
  Chunk = `S_State, u32 tick, u32 ackSeq (last command seq processed), u8 index, u8 count`, then (index 0 only) resources / reputation / unit levels, `u16 n` entity records, `u16 n` effects.
  Chunks apply on arrival; entities missing from a tick are removed only when every chunk of that tick arrived (`SnapshotTracker`), so a lost chunk delays its entities by one snapshot and never deletes anything. Effects in a lost chunk are lost (cosmetic).
  All other messages (chat, fog, roster, queues, defeat, ...) stay reliable. The client smooths `RPos` towards `Goal` (`ClientWorld::interpolate`) until T19b; `ClientWorld::serverTick` / `ackedSeq` are kept for T19b / T19c.
* `BW_NETLOG=1` prints Steam connection state transitions.
* **Identity (T18a):** `C_Hello` = `u64 steamId, u16 len + auth ticket, friends`. The server asks `SteamServerNet::beginAuth` (Steam `BeginAuthSession`, verdict as `NetEvent::Auth`; pending hellos expire after `auth_timeout_s`).
  Profiles are keyed only by the verified SteamID; a second login of an online id replaces the old session. `--local` servers (and selftests) accept only `DEV_TICKET` for ids < 2^32 (`BW_DEV_ID` on the client). Real servers run in Steam authentication mode.
  The server never stores or trusts names: it writes `\x01<SteamID>\x02` tokens (`common/NameToken.hpp`) and clients resolve persona names (`SteamClient::nameOf`, refreshed once per second).

## Conventions

* The server is authoritative; the client sends `C_*` commands and renders `S_*` messages. Network input is validated (range, owner, rate, size).
* Protocol: append new enumerators to the END of the `C_*` / `S_*` group of `Msg` in `Shared.hpp`; T19a was the one planned break, so bump `PROTOCOL_VERSION` only for another deliberate one. New client commands get the seq automatically; new frequent state goes into snapshot chunks, one-off events stay reliable.
* Savegame (BW10): bump `SAVE_MAGIC` (`SaveSystem.hpp`) when the layout changes; an older format is moved aside (`.bad`) and a fresh world starts.
  A damaged optional section is skipped; an unreadable mandatory part stops the server instead of overwriting.
* Tuning belongs in `ServerConfig` + `config/server.cfg`; shared gate/cost rules in `Progression.hpp`.
* Anything that must survive restarts or offline time uses wall-clock expiries, not ticks.
* Inside the client, `ui::` helpers give UI-scale-aware screen size / mouse position; world code uses raw raylib calls.
* ECS: components are plain data, behaviour lives in systems iterating views, singletons live in `registry.ctx()`.
* Code style is defined in `CLAUDE.md`. Docs are part of the code: update them when layout, protocol, save format, config keys, registries, selftests or hooks change.

## Extending the game

One registry per family; ids (`enum Kind`) are persisted and sent, so append only. A `static_assert` in `KindDefs.hpp` checks every id has an entry.

* **New building type** (typically 3 files, no `switch` edits):
  1. `src/common/KindDefs.hpp`: append the id at the end of `enum Kind` (before `K_Count`) and add one `KINDS[]` entry in the same position: stats and cost, `tags` (`KT_*`), `gate`, `menuSlot`, `siteNote`.
     Build menu, context panel, gates and placement checks are generated from it.
  2. `src/rendering/UnitAnims.cpp` (`buildingSprite`): the sprite entry. A procedural look is a `drawXxx` method plus a line in `BuildingRenderer::drawerOf()` in `src/rendering/BuildingDrawers.cpp`.
  3. New behaviour: a component in `src/components/` and a system in `src/systems/` (registered in `Systems.hpp`); per-instance components attach from the `KindFactory` table in `src/systems/KindFactories.cpp`.
* **New unit / NPC type:** the same `KINDS[]` entry (`trainedAt` mask, `archeryLevel`, `thLevel`, `trainSeconds`, `role` / `blurb`), animations in `src/rendering/UnitAnims.cpp` (`animTable()` / `fireTable()`),
  optional `UnitRenderer::drawerOf()` entry, optional `KindFactory` hooks (`attach`, `onTrained`).
* **New ship type:** same as units (T14a replaces the `SHIP_*` arrays in `Shared.hpp` with entries here).
* **New effect type:** add an `EffectType`, then one entry in `src/rendering/FxDrawers.cpp`.
* **New behaviour flag:** add a `KindTag` and test it with `hasTag(kind, KT_*)`; never compare kinds in a system or UI file.
* **New system / mechanic:** component, system registered in `Systems.hpp`, replication in `Replication.cpp`, save entry in `SaveSystem`, tunables in `ServerConfig` + `server.cfg`, an invariant if it references entities, a selftest.
* **New sound cue (from T28a):** one entry in the sound table (event or effect type -> sample, volume, pitch range); samples come from `tools/gen_sounds.py`.
* **New objective / hint (from T26):** one entry in `src/common/Objectives.hpp` or the hint table; progress goes through the objective event bus, never polled in UI code.
* **Draw queue rule:** renderers enqueue `DrawItem{sortY, callable}`; the callable calls one named method and has no logic.

## Test hooks (env vars and flags)

Client: `BW_SHOT`, `BW_SHOT_FRAMES`, `BW_CAM`, `BW_ZOOM`, `BW_CMD`, `BW_MOUSE`, `BW_UI`, `BW_SCALE`, `BW_MENU`, `BW_SITE`, `BW_THTAB`, `BW_THHOVER`, `BW_THCLICK`, `BW_WIN`.
`BW_SITE` verbs: `build`, `upgrade`, `train:<building kind>:<unit kind>@<frame>`, `repair`, `cancel`, `ctx`, `donate`, `alloc`, `dispose`, `quota`.
Server: `BW_RICH`, `BW_AGGRO`, `BW_REVEAL`, `BW_RAIDNOW`, `BW_SEEALL`, `BW_BASETEST`, `BW_BASESPEED`, `BW_BASEDEBUG`, `BW_HURT`, `BW_SPAWN`, `BW_ARMY`, `BW_PATROLNOW`, `BW_WORLDLOG`, `BW_DEFEAT=<seconds>[,offer]` (defeat every online player once the world clock passes it; `,offer` also asks for the first resettlement site), `BW_INVARIANTS` (log invariant violations once per second). Flag: `server --selftest <name|list|all>`.
Instant timers for fast testing are `debug_instant_*` in `config/server.cfg`.
Client `BW_DEV_ID=<n>` (n < 2^32): identity for `--local` servers without Steam login. `BW_NETLAG=<ms>` / `BW_NETLOSS=<percent>` (either executable): Steam fake send lag / loss, set on both sides for a symmetric link. Hooks arrive with their tasks and are added here then: `BW_PACING` (T25a).

## Planned architecture

The design of each upcoming system is in its task spec (`TODO.md` / `BACKLOG.md`), which is the single source of truth. Principles that apply to all of them:

* Server owns state; the client renders, predicts (T19c) and sends commands.
* Threats come from one place, the Pacing Director (`Pacing` singleton in `registry.ctx()`, real-time persisted timers, offline pause); patrol, faction and raid code ask it instead of rolling their own timers.
* Persistent identity is the authenticated SteamID (T18a); names are resolved client-side from Steam.
* Shared `Ruin` component + `K_Ruin` kind (T18b, `DefeatSystem`: ruin, S_Defeat, C_Resettle / C_ResettleAccept) is reused for destroyed buildings (T20d).
* Audio and feedback are client-only presentation driven by server fx events; no audio device = disabled.
* Tactical slow-motion (T23a) is client presentation only.
